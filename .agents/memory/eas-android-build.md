- **Why the first init failed:** a placeholder `extra.eas.projectId` makes `eas project:init` think it's already linked, then GraphQL fails on "Invalid UUID appId". Remove the field first, then `project:init --non-interactive --force`.
- **expo-share-intent duplicate ShareExtension:** the plugin injects its own iOS appExtension; ANY manual `extra.eas.build.experimental.ios.appExtensions` ShareExtension entry makes `expo config` fatal ("more than one appExtensions"). Remove the manual block entirely — deduping to one still fails.
- **Git is blocked:** eas-cli's default VCS mode touches `.git/index.lock`, which the agent sandbox forbids. Always run with `EAS_NO_VCS=1`.
- **Upload exceeds bash timeout:** project archive is ~1.0 GB (monorepo, no `.easignore`), compress+upload ≈ 90s+. `nohup`'d children get reaped when the bash call ends — run the build via a registered validation workflow (`setValidationCommand` + `restart_workflow`) with `--no-wait`, then poll `eas build:view <id> --json` (calls flakily time out; wrap in `timeout 60`, retry).
- Preview profile = APK, signed with an EAS-generated remote keystore; production profile = AAB for Play Store.
- **How to apply:** future builds are just `EAS_NO_VCS=1 npx -y eas-cli build --platform android --profile preview --non-interactive --no-wait` from artifacts/1inme-mobile. Consider adding a `.easignore` to cut the 1 GB archive.
- **Dialer standalone (`sayzio-dialer-standalone`)**: as of Aug 2026 project `@eefind/sayzio-dialer`, projectId `dac41f13-73e0-4fae-ad1b-0c686e37cc6b` (fresh project = NEW keystore), own eas.json (preview=APK). Its node_modules is NOT installed by root pnpm — plain `pnpm install` there silently installs nothing (workspace detection walks up); use `pnpm install --ignore-workspace` first or eas/expo config dies with "Cannot find module expo/config-plugins" from plugins/withAndroidQueries.js. - **npm ci "Exit handler never called" on the EAS builder — TRUE root cause is the Replit package firewall**: lockfiles generated in this workspace record `resolved` URLs like `http://package-firewall.replit.local/npm/...`, unreachable from the EAS builder (ENOTFOUND) — npm 10 dies with the cryptic "Exit handler never called!"; downstream symptoms `expo: not found` / "Read app config" errors are just the failed install. Fix: `sed -i 's|http://package-firewall.replit.local/npm/|https://registry.npmjs.org/|g' package-lock.json` before building (re-check after any local npm install). Adding `"eas-build-pre-install": "npm install -g npm@11"` to package.json makes the builder print the real ENOTFOUND instead of the opaque crash — keep it.
- **Decoding EAS remote build logs**: fetch via GraphQL `POST https://api.expo.dev/graphql` with `Authorization: Bearer $EXPO_TOKEN`, query `{builds{byId(buildId:"..."){logFiles error{message}}}}`; the logFiles URLs are BROTLI-compressed JSONL (magic bytes `0b 48 49`; `pip install brotli`, decompress, each line is a JSON log record).

- **project:init --force duplicates appExtensions**: re-running `eas project:init` (e.g. after switching accounts) can re-inject the expo-share-intent ShareExtension block into app.json, creating a duplicate → every `eas build` fails at "expo config --json exited with code 1" with ZERO output (SilentError swallowed). Diagnose by temporarily patching logCmdError in @expo/cli build/src/utils/errors.js to write the error to a file; fix = delete the whole extra.eas.build.experimental block.

- Installing npm packages inside Replit rewrites `package-lock.json` "resolved" URLs to `http://package-firewall.replit.local/npm/...`; EAS build workers cannot resolve that host and fail at INSTALL_DEPENDENCIES (ENOTFOUND). Now caught statically by the mobile app's `check-eas-lockfile-registry.mjs` guard (in test:unit, CI expolink job, and the `eas-lockfile-registry-guard` pre-merge validation); run it with `--fix` to sed the URLs back to `https://registry.npmjs.org/` (integrity hashes stay valid).
- **"App not installed" fix (dialer)**: every early dialer APK shipped versionCode 1 (remote appVersionSource, never bumped) — Android refuses to install same/lower versionCode over an existing copy. Fix = `"autoIncrement": true` in the preview profile (works with remote version source; `build:version:set` has NO --non-interactive flag). Keystore stayed constant across builds ("Build Credentials Df3Ev7O_KD"); verify signing-cert equality by hashing the DER cert scanned out of the APK Signing Block window before the `APK Sig Block 42` magic (v2-only-signed APKs have no META-INF/*.RSA, keytool -printcert -jarfile prints nothing).
- **Gradle codegen "expand is not a function" (minimatch@3)**: the workspace-root security override `brace-expansion: 5.0.8` in pnpm-workspace.yaml breaks minimatch@3 (needs brace-expansion v1) — RN codegen tasks (slider/async-storage/gesture-handler generateCodegenSchemaFromJavaScript) crash on the EAS builder. Fix: scoped override `'minimatch@<4>brace-expansion': 1.1.12` + `pnpm install --lockfile-only`. Same trap applies to any glob@7 consumer.
- **CI Node version for zio-browser tests**: jsdom@30/undici@8.9 need Node >=22 (`webidl.util.markAsUncloneable`); GitHub workflow setup-node must be 24, not 20, or vitest's forks worker dies while all tests "pass".

- **Free-plan monthly build quota (Aug 2026):** `eas-cli build` fails with a generic "Error: build command failed." AFTER upload/fingerprint when the account has used its free Android builds for the month (quota line appears just above). Deterministic until the monthly reset — not a code issue; do not retry-loop.
- **Validation retries burn quota:** the `eas-apk-build` validation command queues a REAL build on every completion-validation attempt — a retry loop against flaky e2e suites can exhaust the monthly free-plan quota mid-task. If only e2e flakes remain, wait out contention instead of re-running the full battery repeatedly.

## Free-plan build quota exhaustion blocks validation
The `eas-apk-build` validation command fails deterministically once the Expo account's Free-plan Android build quota for the month is used up ("This account has used its Android builds from the Free plan this month ... Error: build command failed" AFTER a successful upload). No code change fixes it; it resets on the 1st. Treat as an external blocker (audited skip_validation_reason), not a regression — the build config is fine if compress/upload/fingerprint all succeed.
