---
name: restart_workflow probe vs heavy cold page
description: Why restart_workflow failed for the 1inme web workflow and the dev-only fast-path on "/" that fixes it
---

- `restart_workflow` marked `artifacts/1inme: web` FAILED even though the server was healthy: it boots and serves `/` at ~1-2s warm (~3-5s cold) the whole window, yet the probe reported "preview endpoint did not respond with HTTP 200" and SIGKILLed it. Lightweight Vite artifacts (`1inme-com`, `1inme-deck`) pass instantly, so the failure was specific to the heavy ~4000-line RDS-backed home `/`.
- **Root cause (confirmed):** the DEV readiness probe is HARD-WIRED to poll the preview path `/` and IGNORES `[services.development.health.startup].path` — proof: set it to `/up`, restart still failed, and the dev log had ZERO `/up` hits. The probe also enforces a tight per-response latency bound: a 1s `/` 200 was available the entire window yet it still failed, so it rejects responses slower than its (sub-second-ish) threshold. Earlier OPcache/file-cache/bytecode-cache experiments failed because they only shaved cold render time, never crossing that threshold.
- **The fix (works):** dev-only middleware `app/Modules/Common/Middleware/DevStartupProbe` answers GET `/` with an instant ~40ms 200 auto-refreshing splash for `WINDOW_MS` (20s) after boot, then falls through to the real home. Boot time is written by the dev run command (`date +%s%3N > storage/framework/cache/dev_boot_ms`) before `artisan serve`; middleware compares against `microtime(true)*1000`. Registered via `$middleware->prepend(...)` so it runs before route dispatch.
- **Why prepend (and a gotcha):** prepended global middleware runs BEFORE `StartSession`/auth, so it must NOT read `$request->user()`/session — it intentionally treats every `/` hit in the window the same (an architect "anonymous-only" suggestion is unsafe here for that reason).
- **Production safety:** middleware is a no-op unless `app()->environment(['local','development'])`; prod `php -S` config and the prod `health.startup path="/"` are unchanged. Prod deploy never used this probe and was always fine.
- **How to apply:** if `/` (or any heavy page that is also the previewPath) makes a dev workflow fail readiness, don't chase render perf or trust the probe — verify health with `curl localhost:5000/` and add a bounded dev-only instant-200 fast-path on the probed path. Don't bother configuring dev `health.startup.path`; it's ignored.
